# ShowKontrol MCP bridge

This server connects an MCP client to the ShowKontrol R27 REST API. It also creates REAPER project files for manual import into the Cue Editor. It is an early bridge, not a complete show-authoring system.

## Requirements

- Node.js 20 or later.
- ShowKontrol R27 with a licence that permits the requested operation.
- A running ShowKontrol web engine. Local plugin pairing or the web server must be enabled in ShowKontrol.
- For remote control over the web server, enable Allow Remote Control and configure an access token in ShowKontrol.

Review the network and token settings before you enable remote access. The manual describes a local-only plugin mode. During a local pairing test, the API reported `localOnly: true` while macOS reported a wildcard listener on port 8090; remote acceptance was not tested. Check network exposure on the target computer.

## Run

Run `npm ci` in this directory, then start `node server.js` through an MCP client. Use the absolute path to `server.js` in the client's configuration. The server uses standard input and output for MCP; do not use the terminal for interactive commands while it runs.

For example, a client that supports the common `mcpServers` configuration can use this entry:

```json
{
  "mcpServers": {
    "showkontrol": {
      "command": "/absolute/path/to/node",
      "args": ["/absolute/path/to/showkontrol-mcp/server.js"],
      "env": {"SHOWKONTROL_USE_LOCAL_PAIRING": "1"}
    }
  }
}
```

Replace both paths with paths on the target computer. Run `command -v node` to find the Node.js executable. Install the project there with `npm ci`. The exact configuration file and restart procedure depend on the MCP client. This example uses local pairing; enable it in ShowKontrol first. For a network connection, set `SHOWKONTROL_URL` and supply `SHOWKONTROL_TOKEN` through the client's private environment. Never commit a token.

For Codex CLI, replace the two example paths and run:

```sh
codex mcp add --env SHOWKONTROL_USE_LOCAL_PAIRING=1 showkontrol -- "/absolute/path/to/node" "/absolute/path/to/showkontrol-mcp/server.js"
```

For Claude Code, replace the two example paths and run:

```sh
claude mcp add --scope user --transport stdio showkontrol -e SHOWKONTROL_USE_LOCAL_PAIRING=1 -- "/absolute/path/to/node" "/absolute/path/to/showkontrol-mcp/server.js"
```

These commands register a local stdio server. Use `codex mcp get showkontrol` or `claude mcp get showkontrol` to inspect the registration. The output can include environment values; do not share it if it contains credentials. Restart the client if it does not show the tools. Use `showkontrol_discover` to check the connection. The CLI options were checked against the installed clients; these exact registration commands have not been run on a clean computer.

Environment variables:

- `SHOWKONTROL_URL`: HTTP(S) origin. Default: `http://127.0.0.1:8090`.
- `SHOWKONTROL_TOKEN`: access token, if required. Store this in the client's private environment, not in a shared configuration file.
- `SHOWKONTROL_USE_LOCAL_PAIRING=1`: read the current user's ShowKontrol Stream Deck pairing file. This only works with a loopback URL. The file must be enabled. When no URL is specified, its port is used.
- `SHOWKONTROL_PAIR_KEY`: explicit local pairing key, if required.
- `SHOWKONTROL_TIMEOUT_MS`: request timeout from 100 to 120000 milliseconds. Default: 5000.
- `SHOWKONTROL_OFFLINE_MAX_BYTES`: maximum offline XML input or output size in bytes. Default: 134217728 (128 MiB). This does not change the 5 MiB live API response limit. Raw XML and part inspection can return large MCP messages; client limits may be lower.

No credentials are needed for offline file tools.

## Offline authoring prompt

Clients that support MCP prompts can discover `author_offline_show` with `prompts/list`. Supply `showPath` and `goal` to `prompts/get`. The prompt guides the agent to inspect the source and donor material, select supported copy tools, and inspect and validate the result. It does not read or change a show by itself. Client support for displaying or invoking prompts varies; you can also ask an agent to follow the same steps directly using the tools below.

The tools support some offline edits, not full show authoring. Validation has partial coverage and does not prove that a show will load or run. Test the resulting copy in ShowKontrol and report the checks performed.

## Tools

- `showkontrol_read`: call a JSON or text GET endpoint under `/api/v1`.
- `showkontrol_read_binary`: read a binary endpoint as an embedded base64 resource, limited to 5 MiB.
- `showkontrol_sample_events`: sample the event stream for up to 30 seconds and 100 events. The server can replay the most recent event of each type when the connection starts.
- `showkontrol_write`: call a POST, PUT, PATCH or DELETE endpoint with a JSON body. Discover the endpoint and its schema first. This tool can change the show and control equipment.
- `showkontrol_diagnose_live_node`: read one node by ID and compare the `node.stopped` parameter with the top-level `stopped` value. The result includes the node ID, title, type, raw values, and a warning when the boolean values differ. Missing, malformed, or duplicate parameter values are `unknown`. A difference does not establish its cause. On R27, the effective getter can reflect license or seal conditions. A live MCP test detected the mismatch on a temporary group node. At nearly the same time, the group type reported licensed and E-STOP was off. These checks do not establish the cause. The test removed the node and restored the baseline node IDs.
- `showkontrol_discover`: read live state, status, nodes, available node types, settings, variables, or the patch.
- `showkontrol_get_plays`: read `/data/plays` with a limit from 1 to 100 (default 20). `showkontrol_get_insights` reads `/data/insights`. Both return the API response without interpreting it. An empty response does not prove that no play history exists. Both tools returned responses through MCP from R27 27.0.11 in a live test. These responses can contain sensitive play data; do not put them or credentials in shared logs. Use the private environment for credentials as described above.
- `showkontrol_get_deck`: read deck detail. Its frame playback data may be stale. Use `showkontrol_get_live_deck` to observe live transport state from `/state`; it returns the exact deck and any `t`, `tick`, and `epochMs` values supplied in the same response.
- `showkontrol_deck_command`: send a documented transport command.
- `showkontrol_list_actions`, `showkontrol_get_action`: list action metadata or read metadata for one action ID. A live R27 27.0.11 test listed actions and read `app.player.load` through MCP. Metadata parameter names do not necessarily match POST JSON fields. Do not infer the request body schema from this metadata. In a disposable R27 27.0.11 session, `app.player.load` accepted `{"appact.deck":"1","appact.track":"__MCP_NONEXISTENT_TRACK__"}` with HTTP 200. No track load was observed. A second request for the test track also returned HTTP 200, while the player remained empty; that track had no verified audio clip. An HTTP success therefore does not establish that the action had its intended effect. Inspect the relevant player, node, or event state after an action.
- `showkontrol_search_actions`: filter the live action catalogue by exact category and text in the ID or label. Results are paginated. An offset can change if the catalogue changes. Read individual action metadata before use; it does not establish the request body schema.
- `showkontrol_run_action`, `showkontrol_session_command`: run an action, launch the show, or switch a screen. The manual does not specify all request bodies; supply the body expected by the running app. In R27 27.0.11, static inspection shows that session launch opens the Live screen for the current session and does not use request body fields. It does not open another session. These calls can control equipment.
- `showkontrol_get_parameter`, `showkontrol_set_parameter`, `showkontrol_set_setting`, `showkontrol_fire_node`: common node and setting operations.
- `showkontrol_node_type_detail`, `showkontrol_create_node`, `showkontrol_delete_node`: inspect a node type and preview, create, or delete a node. Creation requires an explicit `dryRun` value. Optional `params` supplies a JSON object of node settings. In a live R27 27.0.11 dry-run test, supplied settings produced a configured preview with its final title. Creation with these settings and other node types remain unverified.
- `showkontrol_validate_node_settings`: check typed proposed values against the running app’s node-type metadata. Dynamic constraints, XML serialization, and actual app acceptance are not validated.
- `showkontrol_list_connections`, `showkontrol_create_connection`, `showkontrol_delete_connection`: list and edit connections by node ID and pin name or index. Creation requires an explicit `dryRun` value.
- `showkontrol_verify_live_connections`: read connections once and compare up to 100 expected wires by node ID and optional pin index or exact pin label. Omitted pins match any pin. Multiple matches are ambiguous. Malformed live data makes the results incomplete. The response includes the total match count and up to 20 matches with node IDs, pin labels, and pin indices. A live MCP check identified one existing and one absent connection. Presence does not prove a new connection was created or that a signal executed.
- `showkontrol_validate_patch`: send a patch specification with `dryRun: true` for app-side validation.
- `showkontrol_get_patch`, `showkontrol_put_patch`: read or submit the whole running patch. Supply the app’s expected JSON body.
- `showkontrol_inspect_show_media`: read one offline show snapshot and report literal `media.map` rows, exact matching archive parts and their MD5 status, and direct audio clip attributes from track and Program item timelines. Program clips include an item index. Clip `mappingLines` lists rows whose source or target exactly equals the clip's `file` attribute. Duplicate or malformed rows and unreadable parts produce diagnostics. Duplicate archive part names are returned as separate matches. A saved show had a UTF-8, tab-separated source-to-`MEDIA/` mapping, but its target was not an archive part. An absent match does not establish that media is missing or unplayable. The tool does not inspect external files or test playback. It rejects large inventories and uses the offline show size limit.
- `showkontrol_inspect_timeline`: inspect the root metadata, layers, audio entries, direct audio clip attributes and cue element paths in an offline version 1 `.sktl` file. `showkontrol_inspect_show_timeline` provides the same timeline data for a show part. `audioClips` lists each direct `sktimeline/audio/clip` with its zero-based `audioIndex` and XML attributes as strings; `audio` retains the lane attributes. An app save reserialized one synthetic clip with `name`, `file`, `wave`, `grid`, `pps`, `offsetMs`, `vol`, `trimStartMs`, `trimEndMs`, `fadeInMs` and `fadeOutMs` attributes. The app cleared its source path. Playback, attribute meanings, valid values and other clip variants remain unverified.
- `showkontrol_add_timeline_cue_copy`: add a simple cue to a new offline timeline copy. Layer indices start at zero; start and length are in milliseconds. The source checksum must match and the destination must not exist. The shape comes from an app-created cue. In a separate test session, ShowKontrol R27 27.0.11 loaded a generated copy and displayed the added cue at 5 seconds with a 2-second duration. This tool does not create an action graph.
- `showkontrol_add_show_timeline_cues_copy`: add up to 100 simple cues to a new show copy. The destination filesystem must support hard links. The operation does not create action graphs.
- `showkontrol_inspect_cue_graph`: inspect the graph nodes, connections and settings of a cue in an offline timeline or show archive.
- `showkontrol_remove_cue_graph_copy`: remove a cue's graph in a new timeline or show copy. It preserves the cue and checks literal node references in supported XML. External and computed references and app acceptance remain unverified.
- `showkontrol_edit_cue_graph_wire_copy`: add or remove a supported pin-0 cue graph connection. Script and OSC candidate connections were accepted by R27 patch dry runs; cue loading and execution remain unverified.
- `showkontrol_compose_show_copy`: create a track, add cues, optionally copy supported graphs from donor shows, and optionally add the track to an existing set. Each cue can choose a donor or omit its graph. Optional cue `settings` entries contain `nodeId`, `key`, and `value` strings. Use a node ID from the selected donor graph and the key of an existing setting. The copy uses the new node ID and applies the value to that cue. Settings require a graph. A cue can instead specify `mixedGraph` with `nodes` and `wires`, using the same node and wire format as `showkontrol_assemble_mixed_cue_graph_show_copy`. A mixed graph overrides the track default donor; do not also specify a cue donor. For a mixed graph, each `settings` entry uses a zero-based `nodeIndex` in place of `nodeId`. Optional `patchSettings` entries copy an existing setting from an app-saved patch node, adding it to the cue node or replacing its existing setting. Each entry has the target `nodeId` (or `nodeIndex` for a mixed graph), `template` (an absolute path), `templateFormat` (`skf` or `skshow`), `templateSha256`, `templateNodeId`, and `key`. These entries run after `settings`, in array order. The patch node and cue node types must match. The existing patch-setting reference checks apply; values, dependencies, and ShowKontrol acceptance remain unverified. The result includes `nodeIds` in the same order as `nodes`. Inspect every source first. The operation creates an offline copy and requires hard-link support. It does not author media. ShowKontrol opened a fresh test session containing a composed archive and extracted its timeline and set-list parts unchanged. In a separate session using those parts, the app displayed the track, its two cues, and its set-list position. A generated cue with a notification action executed in a separate test; other graphs remain unverified.
  Optional `layerOperations` run in order after track creation and before cues. Each entry has `operation` (`append`, `rename`, `move`, or `remove`) and `layerName`. Append and rename use `newName`; move uses a zero-based `targetIndex`. Append copies an empty named layer to the end. Move and remove update direct cue indices; removal rejects occupied layers. Cue `layer` values are zero-based indexes in the resulting layer list. The layer operations have not been verified in ShowKontrol.
  Optional cue `postPatchSettings` use the same node selector, key, and value format as `settings`. They run after `patchSettings`, so a copied setting can be customized in the same transaction. Values, dependencies, and app acceptance remain unverified.
  Set `set.createIfMissing` to `true` to create the named set if it is absent. An existing unique set is reused. Duplicate set names cause an error. If omitted or false, the set must already exist. Set creation and track composition are published together; a failure leaves no destination file. In a multi-track composition, later tracks can reuse the set created by an earlier track.

For either compose tool, `cues` may be omitted or empty. Creating a track is sufficient; an existing track must have at least one new cue, layer operation, audio clip edit, cue removal, cue edit, or graph setting edit. Edit-only composition has not been validated in ShowKontrol. A failed operation leaves no destination copy. For either compose tool, choose one track mode. To create a track, supply `templateName`, `trackName`, and `partName`, as before. To add cues to an existing timeline, supply `existingPartName` with the exact timeline part name. Do not supply the three new-track fields or `set` in this mode. Optional layer operations, donors, mixed graphs, and cue settings apply to the selected timeline. Existing media, cues, and other parts are preserved by the offline writers. The result identifies this mode with `existingPartName`. This mode has not been validated in ShowKontrol. Each track may include `cueRemovals`, an ordered array of up to 100 `{cueId, deleteGraph?}` entries for existing tracks. Removals run after layer and audio clip edits, before cue edits, graph setting edits, and new cues. Set `deleteGraph: true` to remove a cue with a graph. Literal references in supported show XML are checked. External and computed references remain unchecked. Validate the copy in ShowKontrol. Each track may include `cueEdits`, an ordered array of up to 100 `{cueId, layer?, startMs?, lengthMs?, label?}` entries. Each entry must change at least one existing field. Edits run after layer and audio clip edits and before new cues. They preserve existing cue graphs. New tracks contain no existing cues, so nonempty `cueEdits` require `existingPartName`. This capability has not been validated in ShowKontrol. A failed edit leaves no destination copy. Each track may include `graphSettingEdits`, an ordered array of up to 100 `{cueId, nodeId, key, value}` entries for existing cue graphs. These edits run after cue edits and before new cues. They require `existingPartName` and an existing setting on the specified node. Inspect the graph first. Values and ShowKontrol acceptance remain unverified. A failed edit leaves no destination copy. Each track may include `audioClipEdits`, an ordered array of up to 100 `{audioIndex, clipIndex, attributes}` entries. Indices select zero-based direct audio lanes and their direct clips. Each `attributes` object contains one or more existing attributes chosen from `pps`, `offsetMs`, `vol`, `trimStartMs`, `trimEndMs`, `fadeInMs`, and `fadeOutMs`, with string values. Edits run after track selection and layer operations, before cues. New-track templates cannot contain clips, so nonempty edits require an existing timeline with clips. Inspect the timeline first. The values and ShowKontrol acceptance remain unverified. A failed edit leaves no destination copy.

The direct cue graph and cue node copy tools, batch graph copy tool, and cue graph assembly tools also return a `warnings` array for copied nodes that store a stopped value. Warning scopes use the destination cue and remapped node IDs. For standalone timeline copies, `part` is the destination file path. The two compose tools return a `warnings` array from the final output timelines they edit. Each `stored_stopped_cue_node` warning identifies the part, cue, and node when IDs are present. It reports a stored `stopped="1"` attribute or `node.stopped` setting of `true`. It does not establish the active node state or its effect on execution. The scan uses the same direct cue graph scope as show validation. A scan failure prevents publication. Cleanup warnings are separate.

- `showkontrol_compose_multi_track_show_copy`: compose up to 20 new or existing tracks in one offline copy using the same track and cue options. Each track selects its own mode. Ordered `setlistOperations` run after track composition and support `create_setlist`, `append_track`, `create_set`, `remove_set`, `remove_track`, and `move_track`. Track indices are zero-based. Removing a populated set requires `allowContentRemoval: true`; the last set cannot be removed. Set reordering is unsupported. App acceptance is unverified. At least one change is required; tracks may be empty when operations change the show. Optional `patchOperations` use the ordered operations and restrictions of `showkontrol_edit_patch_batch_copy` before track composition. Node removal checks the patch and supported `.skf`, `.sktl`, `.sksc`, `.skls`, and `.skpr` show parts for ID text. It can reject harmless text. Other parts and external references are not checked. Copied nodes retain internal references and do not include connections or dependencies. Patch values, compatibility, and ShowKontrol acceptance are not validated. It does not author media and requires hard-link support. This multi-track operation remains unverified in the app.
- `showkontrol_edit_cue_graph_settings_show_copy`: change up to 100 existing cue graph settings across timelines, cues and nodes in one new show copy. Each `settings` item has `name`, `cueId`, `nodeId`, `key` and string `value`. Inspect the show checksum first. The batch fails if any setting is missing or ambiguous. The destination must not exist and its filesystem must support hard links. Values and app acceptance remain unverified.
- `showkontrol_edit_cue_graph_setting_copy`: change an existing node setting in a cue graph in a new copy. Inspect first. The tool does not create a missing setting. For `node.stopped`, use the exact string `true` or `false`. The tool updates all supported existing stopped representations together. Batch and compose setting edits use the same rule. Other values are not validated. ShowKontrol acceptance remains unverified.
- `showkontrol_set_cue_graph_node_stopped_copy`: change the explicit stopped state of a cue graph node in an offline timeline or show copy. It updates supported existing `stopped` and `node.stopped` representations together. It rejects missing, ambiguous, or unsupported representations. This does not prove the node will run: ShowKontrol can also stop a node for license or seal conditions. App acceptance is unverified.
- `showkontrol_add_cue_graph_setting_copy`: add a missing fixture-supported setting to a cue graph node in a new copy. Only `trigger.path`, `trigger.on` and `action.category` on their corresponding node types are supported. Values and app acceptance remain unverified.
- `showkontrol_copy_cue_graph_show_copy`: copy a graph from a cue in the same or another show to an empty cue in a new show archive. Set `sourceName` to select the source timeline and `name` for the target timeline. For a separate show, also set `template` and its inspected `templateSha256`. It supports group input, trigger, action, Script processor, and OSC generator nodes. Script and OSC use patch-derived prototypes; cue acceptance and execution are unverified. It scans target `.skf`, `.sktl`, `.sksc`, and `.skpr` XML parts for node IDs and remaps graph nodes and connections. It rejects ID-like references outside node IDs and connection endpoints, except a router target that matches exactly one valid destination patch router name. This conservative check can reject harmless text. Other external dependencies are not checked. An MCP test copied the notification graph within an app-saved test show and read back three nodes and two connections; validation reported only partial scene coverage. Reopening its output in the app remains unverified.
- `showkontrol_copy_cue_graph_timeline_copy`: copy a supported graph between standalone timeline files. The ID scan covers the target timeline only. It rejects ID-like references outside node IDs and connection endpoints and rejects router targets because it cannot check the destination patch. This conservative check can reject harmless text. Check the rest of the show for collisions before using the copy in a show. App acceptance remains unverified.

For supported cue and Program item graph copies, set `allowOpaqueNodeText: true` to preserve node-like text in a scalar Script `proc.script` or OSC `gen.address` setting. For mixed assembly, set it on each donor that needs it. The tool does not rewrite that text. If the option bypasses a reference check, the result includes `opaque_node_references_unverified`; inspect the text and its dependencies. Structural references remain checked. Other copy paths may not support this option.
- `showkontrol_copy_cue_graph_node_show_copy`: copy a supported node into an existing cue graph in a new show copy. It copies no wires and rejects ID-like internal references. App acceptance remains unverified.
- `showkontrol_copy_patch_node_to_cue_show_copy`: copy an action, trigger, Script processor, or OSC generator node from an offline patch into a cue graph. It copies no wires and rejects ID-like internal references. Script and OSC support uses stopped, disconnected patch nodes saved by R27; cue acceptance and execution are unverified. In one test, a copied notification action fired from a generated cue; other nodes and dependencies remain unverified.
- `showkontrol_copy_patch_setting_to_cue_show_copy`: copy one existing patch-node setting into a matching cue node in an offline show copy. Script processor and OSC generator nodes must also match the donor kind. It rejects `node.stopped`; use the cue node stopped-state tool for that state. For `route.router_target` on an action, the nonempty target must exactly match one destination patch router’s `router.name`. The check rejects unrelated node references and requires a unique matching router name and valid router structure. Node-type matching does not establish action-category compatibility. This is a structural check; it does not establish how ShowKontrol resolves router targets. A live test with target `A` worked for a router whose name and title were both `A`; other variants, values, dependencies, and app acceptance remain unverified.
- `showkontrol_assemble_cue_graph_show_copy`: assemble supported nodes and pin-0 wires from template shows into a cue in one offline show copy. It can create a graph in an empty cue. It requires hard-link support; external dependencies and app acceptance remain unverified.
- `showkontrol_assemble_mixed_cue_graph_show_copy`: assemble supported nodes from cue graphs and patches into one cue graph. It requires hard-link support; one trigger-and-notification graph executed in a test; other node behavior and external dependencies remain unverified.
- `showkontrol_remove_cue_graph_node_copy`: remove an unreferenced node from an offline cue graph copy. The reference check is conservative and covers supported XML parts only. External references and app acceptance are not verified.
- `showkontrol_copy_cue_graphs_show_copy`: copy up to 100 supported cue graphs into one show copy. The destination filesystem must support hard links. App acceptance remains unverified.
- `showkontrol_inspect_show_timeline`, `showkontrol_add_show_timeline_cue_copy`: inspect a named `.sktl` part and add a simple cue in a new `.skshow` copy. The archive checksum must match. The tool validates part checksums and updates the changed part checksum. Other parts are preserved. ShowKontrol displayed a generated cue in a separate test session.
- `showkontrol_edit_show_timeline_cues_copy`: apply 1–100 ordered edits to cue fields across timeline parts in one new show copy. Each edit has `name`, `cueId`, and at least one of `layer`, `startMs`, `lengthMs`, or `label`. Inspect the source checksum first. Each step checks the previous copy. The tool preserves cue graphs and publishes only after all edits succeed. The destination must not exist and its filesystem must support hard links. An MCP test edited a cue in a copy of an app-saved test show and read back its unchanged graph. App acceptance remains unverified.
- `showkontrol_edit_timeline_cue_copy`, `showkontrol_delete_timeline_cue_copy`: edit or delete a cue in a new copy. Moving or editing a cue preserves its action graph. Deleting a cue with a graph requires `deleteGraph: true`. The tool checks literal references in supported XML. A standalone file check covers only that timeline. External and computed references remain unchecked. App acceptance remains unverified.
- `showkontrol_edit_timeline_layer_copy`: append, rename, move, or remove an unoccupied layer in a new timeline or show copy. Move and remove update direct cue layer indices. Unknown references outside the timeline and app acceptance remain unverified.
- `showkontrol_create_show_track_copy`: add an empty track using an inspected empty timeline template. The set list is unchanged. ShowKontrol R27 27.0.11 loaded a generated test show and displayed the new track in its catalog; playback and other track variants remain unverified.
- `showkontrol_remove_show_track_copy`: remove a timeline part from a new show copy. Supply its exact part `name`, the inspected show SHA-256, and an explicit `allowContentRemoval` boolean. The tool rejects literal references in supported XML, including set lists. Remove those references first. It does not check external, binary, or computed references. Application acceptance is unverified.

For track creation or composition, an external empty template can be supplied as `templateDonor` with `file`, `format` (`sktl` or `skshow`), and inspected `sha256`. For a show donor, add the exact timeline part `name`. Use either `templateName` or `templateDonor`. The external-template path has not been tested in ShowKontrol.
- `showkontrol_inspect_cue_references`: scan decoded XML show parts for literal occurrences of a cue ID and its graph node IDs outside the selected cue. Results may include unrelated text or definitions. Encoded, computed, external, and binary references are not covered; an empty result does not prove a cue is unused. The scan limits identifiers and returned records and reports truncated output.
- `showkontrol_rename_show_track_copy`: rename a unique timeline and all exact matching entries in supported version 2 set lists in a new offline show copy. An MCP test on an app-saved show updated the timeline and matching set-list entry while preserving other parts and valid checksums. Unsupported literal references in supported XML block the rename. External and computed references and app acceptance remain unverified. The destination filesystem must support hard links.
- `showkontrol_inspect_show_setlist`, `showkontrol_add_show_setlist_track_copy`: inspect sets and append an existing track to a set in a new show copy. App acceptance remains unverified.
- `showkontrol_create_show_setlist_copy`: create a version 2 set list with one set and optional existing track entries in a new show copy. The show must not already contain a set-list part. Use an absolute destination and an inspected source SHA-256. Multi-track composition also supports an ordered `create_setlist` operation before other set-list edits. Empty-set behavior, active-set behavior, and ShowKontrol acceptance are unverified.
- `showkontrol_edit_show_setlist_copy`: create or remove a set, remove a track entry, or change the order of track entries in a new show copy. Removing a populated set requires `allowContentRemoval: true`; the last set cannot be removed. The active index is adjusted using static R27 evidence. Set ordering and app acceptance remain unverified.
- `showkontrol_plan_live_graph`: preview configured nodes and resolve local `ref` values to their final titles. Use `{node: localRef, pin?}` for a planned node and `{existingNode: ID, pin?}` for an existing live node. Connections can use either endpoint type. To validate connections between existing nodes, pass an empty `nodes` array and use `existingNode` for both endpoints. The `nodes` and `connections` arrays cannot both be empty. A live MCP dry run validated an existing-node-only connection without changing the connection list; it was not applied. The result contains `nodes` and `connections` for `showkontrol_compose_live_patch`, the mapping, and the app's dry-run result. Each preview has a `paramComparison` that reports requested parameters the app changed, omitted, or returned ambiguously. Inspect it even when the patch dry run succeeds. A live test showed that an invalid boolean was accepted by the dry run but returned as `false` in the preview; the comparison reported the mismatch. Preview node IDs are temporary and are not used in the plan. The app state can change between the dry run and a later write. A live MCP test connected an existing Player 1 node to a new group, verified the connection, then removed the group and restored the node and connection baseline. Graph execution was not verified.
- `showkontrol_create_staged_live_graph`: create up to 50 live nodes in sequence, then create up to 100 connections in sequence. Each node has a unique local `ref`, `request`, `title`, and optional `params`. Use `{node: ref, pin?}` for a new node and `{existingNode: ID, pin?}` for a live node. The tool uses the IDs returned by node creation, so nodes can have the same normalized title. It does not use preview IDs. For each supplied parameter, it checks the returned value exactly before continuing. ### Media project input

Use `mediaTracks` in the `showkontrol_create_rpp` arguments. Each track has a `name`, a `kind` of `audio` or `video`, and an `items` array. Each item has a `file` path, `seconds`, and `duration`. The generator does not check media existence, media duration, codecs, or whether the destination Mac can read a path. Use paths that exist on that Mac, or paths relative to the RPP file. Place the media where ShowKontrol can find it. The import dialog can still list missing media. The file only references media; it does not copy or embed it.

The media preflight checks each absolute path as given, or resolves a relative path against the intended RPP directory. It reports the checked path and whether it is a readable regular file, is not a regular file, was not found at that path, or could not be checked. It follows symlinks and reports duplicate references separately. It accepts up to 100 tracks and 500 items, with paths and names limited to 4096 characters. Unknown or unavailable duration does not establish whether the item fits. Probes share a five-second time budget per request and permit only local file protocols. The check does not verify media format, codec, or import into ShowKontrol.

For a show donor, supply its timeline part name as `donorName`. Set `replaceExisting: true` to replace a graph. The tool rejects unsupported references. Inspect trigger settings and dependencies. Runtime ID behavior and application acceptance are unverified.

`showkontrol_embed_program_timeline_copy` embeds a timeline root in one item of a new standalone Program copy. Supply the inspected Program `source` and `sha256`, zero-based item `index`, `donor` and `donorSha256`. The donor can be a standalone `.sktl` or a `.skshow`; for a show, also supply its exact `donorName` part name. The destination must be a new absolute `.skpr` path. Set `replaceExisting: true` to replace an item timeline. This uses static format evidence only; application acceptance is unverified. It does not copy media or remap IDs. An MCP test embedded an app-saved timeline and inspected its three cues and four layers; the generated Program was not opened in ShowKontrol. External references, media, and runtime IDs are unverified; the application may change node IDs.

`showkontrol_embed_remapped_program_timeline_copy` embeds a donor timeline and assigns fresh cue-graph node IDs against an inspected target show and source Program. Supply their paths and SHA-256 values, the donor and its SHA-256, the item index, and a new `.skpr` destination. Set `remapCueIds: true` to assign fresh cue IDs when reusing a timeline. The tool rejects unsupported references and returns the ID mappings. Media is not copied. External dependencies, runtime ID behavior, and ShowKontrol acceptance remain unverified.

`showkontrol_inspect_show_program` inspects the canonical `content/Program.skpr` part in an offline `.skshow`. Use `showkontrol_extract_show_program_copy` with the inspected archive SHA-256 to extract its exact bytes to a new standalone `.skpr` file. Edit that file with `showkontrol_create_program_copy`. Use `showkontrol_attach_show_program_copy` to attach the edited Program to a new archive copy. Supply the inspected archive SHA-256 and Program SHA-256. Set `replaceExisting: true` to replace an existing Program. These archive tools check all part checksums and reject duplicate names. Extraction and attachment preserve Program bytes; attachment preserves unrelated parts. Destinations must not exist and publishing requires hard-link support. ShowKontrol application acceptance is not verified.
